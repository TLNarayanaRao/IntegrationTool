Installed product documentation

SAP ECC integration

Configure, operate, and qualify IDoc, ALE, RFC, and BAPI workloads through the customer-supplied SAP Java Connector.

Activity coverage

IDoc and ALE

Listen, parse, convert, render, post, acknowledge, and confirm. Metadata fetched from ECC defines the mapping tree and fixed-width SDATA layout.

RFC and BAPI

Invoke import/changing/table parameters or receive registered-server calls. Request/reply tasks must end in Reply so exports reach SAP.

Transaction delivery

Request/reply, tRFC, and qRFC are distinct modes. Durable TID state prevents duplicate processing; qRFC requires a queue name.

Read Table

Choose fields, ABAP WHERE clauses, skip, and count. Output records use SAP field names for direct mapping.

Typical flows

IDoc Listener → IDoc Parser → Mapper → business target → End
RFC/BAPI Listener → validate and process → Reply from RFC/BAPI
business source → Mapper → Post IDoc to SAP → End

Runtime installation

  1. Place matching sapjco3.jar and sapjco3.dll in C:\ProgramData\Integration Fabric Studio\drivers\sap. Linux uses libsapjco3.so.
  2. Use a currently supported JCo 3.1 patch and a JDK/JRE supported for that patch. Use the same CPU architecture for Java, JCo, and the native library.
  3. Configure application-server or message-server credentials, then run Test Connection. Retain its JCo version, Java version, architecture, and loaded-JAR diagnostics.
  4. For listeners, configure the SAP gateway and Program ID in SM59 and the required WE20/WE21 partner profile and port.
  5. Fetch and save the actual IDoc or RFC metadata before packaging.

Operational safeguards

  • Inbound queues, diagnostic history, and connection counts are bounded.
  • A task commits its SAP delivery only after successful completion. Failure, cancellation, missing Reply, or timeout rolls it back.
  • Keep the TID store on durable writable storage and back it up with the deployed application state.
  • Stop/undeploy closes JCo listener processes; startup reconnects with exponential retry.
  • Use environment properties for credentials, gateway values, queue names, timeouts, and capacity settings.
Production qualification is required

Mock and unit tests cannot prove compatibility or leak-free behavior for your ECC kernel and licensed JCo build. Run a 24–72 hour soak with peak-size IDocs, concurrent RFC/BAPI calls, restarts, network faults, duplicate TIDs, and qRFC backlog. Monitor JVM heap/GC, RSS, threads, handles, throughput, SM58, SMQ1, and SMQ2 before approval.

Certification and product identity

Integration Fabric is not SAP-certified merely because it uses JCo. SAP allows JCo for bidirectional communication with external applications, but customers must obtain it from SAP, comply with their SAP licensing, and must not redistribute it. This is Integration Fabric documentation for its own implementation; Integration Fabric is not SAP or TIBCO software.
